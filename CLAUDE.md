# Dotfiles

macOS Development Environment Configuration
Shell-based automation for personal dotfiles and dev environment.

## Quick Commands

```bash
./dotfiles.sh              # Install or re-sync this machine (idempotent, backs up, never deletes)
./dotfiles.sh --print-links  # Print the link map (repo source, home destination)
./test-dotfiles.sh         # Validate this machine
shellspec                  # Unit tests
e2e/run.sh                 # Docker end-to-end test (E2E_SKIP_BUILD=1 reuses the image)
```

## Key Context

- Apple Silicon macOS only; Homebrew prefix `/opt/homebrew`
- `LINKS` in `dotfiles.sh` is the single link map; `test-dotfiles.sh` sources `dotfiles.sh`
- Pinned versions live in `dotfiles.sh`: `RUBY_VERSION`, `NODE_VERSION`
- Config files live under `config/` and `home/`, mirroring destination paths, and are symlinked
- Git identity is machine-local in `~/.config/git/config.local`, written by the installer
- Brewfile is generated by `brew bundle dump`; see README "Adding a package" for the four manual edits
  (strip `#` lines, drop `restart_service:`, drop `npm "corepack"`, re-add `reminders-cli`) and the two
  dead taps (`homebrew/services`, `sass/sass`) the dump re-adds from this Mac

## Entry Points

- Main: `dotfiles.sh`
- Tests: `test-dotfiles.sh`, `spec/`, `e2e/run.sh`
- Target: `$HOME` and `$HOME/.config/` (after installation)

## Safety

- Modifies `$HOME` directory
- Displaced files are moved to `<path>.backup.<timestamp>`; nothing is deleted
- Never run `rm` in this repo's scripts
